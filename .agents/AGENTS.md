# Tank-enclosure project guidance

This repository owns CAD data and project configuration. Reusable tools belong
in `vault-cad-tools`, `mechanical-docs` and `mechanical-cad`. Read README.md,
vault-project.toml, and .agents/PLANS.md. .agents/HISTORY.md holds the finished
checkpoints; read it only to trace how something came about.

The direction of the wider work and the layout this repository is to follow
(where STEP files and metadata go) are kept in the sibling `mechanical-cad`
repository: `docs/direction.md` and `docs/layout-proposal.md`. This project is
the test case for that layout. Work that spans repositories runs from an agent
session rooted there (Peter, 2026-11-10).

Use the managed Guix environment on Linux. Use a separate checkout on each host;
on Windows run the tools through their locked Pixi environment.
Never concurrently modify a working tree through the network share. Changes
remain uncommitted unless the user asks otherwise. No automatic pushes.

`main` is what the published site is built from: the Pages workflow runs when a
push to `main` changes `docs/` or `mkdocs.yml`. Do structural work, such as the
layout conversion, on a branch. The pages under `docs/` other than
`docs/manual/` are generated by `assembly/site_pages.py`; do not edit them by
hand.

Preserve Vault-derived references: nothing under references/ is edited by
hand. Author changes under designs/. The layout of both is specified and
validated in `mechanical-cad`; the scripts under assembly/ read the scene
flattened from them into .cache/ (`make reference-scene`).

`make` alone lists the short commands. `make assemblies` lists the assemblies
that can be built as one STEP file and one FreeCAD document and says which are
built; `make assembly [KEY=<key>]` builds one into the ignored
`.cache/assemblies/`. Those files are derived and for reading: never commit
them, and never treat one as a source. `make open [KEY=<key>]` is for a
person at the machine: it opens the FreeCAD window and returns only when the
window is closed, so an agent builds with `make assembly` and names the file
instead. The Makefile finds `mechanical-cad` beside this repository or
through the ignored `local.mk`.
Record real source IDs and exporter evidence; never invent them to populate a
manifest. Credentials, downloaded native files, and machine-specific state stay
outside tracked files. Do not treat Git text merging as geometric merging.

Validate incoming STEP checksums before importing and check geometry with
FreeCAD. Validate publication in Inventor on Windows. Do not report round-trip
success based only on a syntactically plausible STEP header.

Use explicit Vault destinations for writes; generated reference STEP files and
Inventor originals are not publication targets for authored designs.

.agents/PLANS.md holds the current state, the next work and the open items, and
nothing else. When a checkpoint is finished, move its record to
.agents/HISTORY.md. Do not write commit ids or "uncommitted" into tracked files:
Git knows, and the text is wrong as soon as Peter commits. A checkbox is a task;
a measurement or a decision is a sentence.
